## SCRUM-676 (REQ-596) — nota, comparte causa raíz con el hallazgo crítico

El mockup (`2A__CRM_Pipeline.html` etc.) modela el sidebar como 7 ítems planos de un solo nivel
("CRM", "Ventas & Diseño", "Compras"...), cada uno clickeable y navegando directo a la pantalla de
inicio de su módulo — la sub-navegación (Dashboard CRM/Pipeline/Lista de Proyectos/Clientes) vive
en una barra "subtabs" aparte, debajo del topbar. La implementación real usa el patrón de sidebar
en acordeón ya establecido desde SCRUM-58 (grupo con header colapsable + sub-ítems navegables
directos) — esto es exactamente el tipo de variante de layout que Luis ya pre-aprobó como ACEPTABLE
en `visual-reviewer.md` ("el mockup tiene el menú en la parte superior, el desarrollo lo tiene como
sidebar — mismo conjunto de opciones, solo cambia dónde vive"), y **no es un cambio introducido por
este batch** — es la arquitectura de navegación que ya tenía toda la app antes de este epic.

Confirmado en código (`Sidebar.tsx` línea 264): el header de cada grupo (`"CRM"`, `"Ventas & Diseño"`)
solo dispara `toggleGroup()` (expandir/colapsar), nunca `navigate()` — no reproduce literalmente el
Escenario 1/2 de REQ-596 ("clic en 'CRM' navega a Dashboard CRM"/"clic en 'Ventas & Diseño' navega a
Inicio"). Sin embargo, el usuario **sí puede llegar** a cada destino con un clic directo sobre el
sub-ítem correspondiente (ya visible, sin necesidad de expandir nada — los grupos arrancan
expandidos) — no hay pérdida de funcionalidad, solo un mecanismo de clic distinto al descrito
literalmente. Bajo la regla de decisión del Visual Reviewer esto clasifica como ACEPTABLE, no
CRÍTICO.

La premisa de la historia ("antes de este cambio, el menú lateral no navegaba a ningún lado, era
decorativo", RN4) tampoco es cierta en este código — el sidebar navega ítem por ítem desde
SCRUM-58, mucho antes de este epic. Vale la pena que PM/Arquitecto confirmen si REQ-596 debe
re-redactarse para esta arquitectura de navegación en vez de dejarlo abierto como posible hallazgo
futuro.

**Único punto real de intersección con el hallazgo crítico**: RN1 de REQ-596 dice que un usuario sin
perfil Gerencia que hace clic en "CRM" debe llegar a Pipeline, no a Dashboard CRM — precisamente
porque Dashboard CRM es Gerencia-only. Como hoy CUALQUIER usuario puede navegar directo a
`/crm/dashboard` (mismo root cause que SCRUM-674 RN5), este matiz de REQ-596 tampoco se sostiene
hasta que se corrija el gate de permiso — no es un hallazgo adicional, es el mismo fix necesario.
